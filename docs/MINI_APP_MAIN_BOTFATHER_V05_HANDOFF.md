# NGO Grants AI — перевірений перехід до Main Mini App (v0.5)

**Стан 8 листопада 2026 року:** серверна частина v0.5 успішно розгорнута в Cloudflare (GitHub Actions [42469920582](https://github.com/Prool-bot/ngo-grants-facebook/actions/runs/42469920582)). API відхиляє неправильно підписані дані Telegram, недозволений Origin та GET на POST-маршруті; стара клавіатурна Mini App v0.4 і старі команди бота працюють. **Реальне замовлення через Main Mini App ще не перевірено.**

## Дані для налаштування без створення нового бота

- Telegram-бот: **@ngogratsAI_bot** (вже існує).
- Назва застосунку: **NGO Grants AI — Грантовий помічник**.
- HTTPS URL Main Mini App: `https://ngo-grants-instant-bot.oleh-protasoff.workers.dev/mini-app/direct`.
- Після активації в @BotFather формат прямого посилання: `https://t.me/ngogratsAI_bot?startapp`.
- Публічний канал: **@ngo_grants**; його CTA поки **НЕ** змінювати.

Telegram офіційно вимагає налаштування Main Mini App у **@BotFather** власником наявного бота. У профілі бота власник обирає налаштування Mini App, вказує HTTPS-адресу й зберігає. Точні назви пунктів меню BotFather можуть змінюватись; орієнтир — «Main Mini App» / «Configure Mini App», а не «Menu Button» і не створення нового бота. Вказаний URL уже служить на робочому сервері.

## Перевірка після активації

Після налаштування лише читати `getMe.has_main_web_app` через Bot API. У [щоденному monitor workflow](../.github/workflows/mini-app-v05-health.yml) відображаються прапори `MAIN_MINI_APP_REGISTERED` та, за можливості, `CURRENT_CONNECTED_SESSION_CAN_EDIT_BOT`. Відсутність прапорця edit у підключеній Telethon-сесії **не означає**, що власник не може керувати ботом з іншого акаунта.

Далі перевірити з реального Telegram клієнта Android/iOS/Desktop: натискання прямого посилання з основного каналу, поява поверх каналу без переходу в приватний чат, анкету й підписаний `initData`, добровільне одне замовлення, серверний `order_id`, D1-чергу, плановий GitHub-обробник і кінцевий PDF / статус відсутності результатів. **Не** робити фіктивні замовлення через API. Перед тестом чітко попередити учасника про денний ліміт.

Тільки після підтвердження реального циклу редагувати вже опублікований допис [3813](https://t.me/ngo_grants/3813) та кнопку в основному каналі; старий `/start` залишити як запасний шлях. Не публікувати дубль анонсу.

## Інваріанти безпеки

Сервер завжди перевіряє підпис Telegram `initData`, актуальну підписку й наявний денний ліміт. Номер замовлення в UI з'являється **лише** після перевіреного запису в існуючу D1-чергу. Для користувача, який ніколи не відкривав бот, DM-повідомлення не потрібне. Клієнт зберігає ідемпотентний ключ для повтору після збою. Серверні токени, персональні дані та сире `initData` ніколи не записуються в GitHub.
