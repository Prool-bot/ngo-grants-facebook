# NGO Grants AI v5.9 — ізольоване приймальне тестування Telegram

**Статус:** підготовлено окремий ручний GitHub Actions workflow; система публічних замовлень **не змінюється**. Активна змінна `NGO_GRANTS_V59_LIVE_DELIVERY` у робочому workflow залишається `false`.

## Підготовка без доступу до production

1. У BotFather створити **окремого тестового бота**, username якого містить `test`. **Не використовувати** токен робочого `ngoGrantsAI_bot`.
2. Створити **новий приватний Telegram-канал** без публічного username. Назва повинна містити `TEST` або `ТЕСТ`.
3. Призначити тестового бота адміністратором із дозволами на публікацію та редагування повідомлень.
4. У GitHub репозиторію, Settings → Secrets and variables → Actions → Repository secrets, створити:
   - `V59_TEST_BOT_TOKEN` — токен **виключно тестового** бота.
   - `V59_TEST_CHANNEL_ID` — числовий ідентифікатор приватного тестового каналу формату `-100...`.
   
   Жодні токени, ID та приватні дані **не публікувати** в Issue, PR, чатах чи коді.

## Запуск безпечного preflight

У GitHub → Actions → **NGO Grants v5.9 — PRIVATE Telegram staging ONLY** → Run workflow вибрати режим `preflight`, поле confirmation залишити порожнім.

Preflight виконує лише read-only методи Telegram Bot API: `getMe`, `getChat`, `getChatMember`. Він перевіряє окремого тестового бота, приватність каналу, його назву, права публікації та редагування. Він **нічого не публікує**.

Очікуваний результат: `V59_PRIVATE_TEST_PREFLIGHT=PASS; NO_MESSAGES_SENT`.

## Фактична доставка двох PDF — тільки в приватному тестовому каналі

Після підтвердження preflight обрати режим `send` та ввести `CONFIRM_PRIVATE_TEST_ONLY`. У workflow автоматично створюються **виключно синтетичні PDF**, після чого:

1. Тестовий бот надсилає прямий каталог до приватного каналу.
2. Надсилає умовний каталог.
3. Додає до першого PDF кнопку з посиланням `https://t.me/c/.../...`, яка відкриває другий PDF.
4. Перевіряє ідентифікатор повідомлення, підтверджений Telegram.

**Без автоматичних повторів:** якщо після `sendDocument` втрачено відповідь API, скрипт зупиняється. Не запускати режим `send` повторно до ручної перевірки двох документів у тестовому каналі. Тестові документи залишаються там для перевірки.

## Відокремлення від робочої системи

- Немає доступу до робочої черги, старого замовлення чи архіву донорів.
- Секрети тестового бота відокремлені від `NGO_GRANTS_AI_BOT_TOKEN`.
- Не відбувається жодних операцій із Cloudflare D1, Worker deployment або `ai_catalogs/state.json`.
- Публічний канал `@ngo_grants` заборонений; перевірка примусово відхиляє публічні username.
- Після проходження staging має бути **окремий PR на активацію**: не змінювати флаг у цьому тесті.

## Критерій готовності

Завершення автоматичного workflow `send` з результатом `V59_PRIVATE_TEST_ACCEPTANCE=PASS`, ручне відкриття обох PDF та переходу за кнопкою в приватному каналі й повторна перевірка відсутності дублювання. Лише після цього розглядати окремий PR на поступову активацію.
