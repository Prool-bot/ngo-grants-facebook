# NGO Grants — тематичні ШІ-каталоги (впровадження)

## Що це

Запит від підписника → 1 запит/добу → перевірка схожих опублікованих каталогів та черги → відбір **виключно** з `archive/telegram/months/*.json` → перевірка явного майбутнього дедлайну **лише за текстом допису** → аналіз релевантності через Cloudflare Workers AI → PDF з активними посиланнями **тільки на @ngo_grants** → опублікування PDF для всіх. До **3 каталогів/добу**, між ними щонайменше 2 години. Бот **не надсилає PDF приватно**.

Канал: https://t.me/ngo_grants. Бот: https://t.me/ngogratsAI_bot.

## Як встановити

1. Перевірити, що бот `@ngogratsAI_bot` має права **Публікувати повідомлення** в `@ngo_grants` (без зайвих адміністративних прав).
2. Файли з архіву цього випуску скопіювати **у корінь** GitHub-репозиторію `Prool-bot/ngo-grants-facebook`, **із збереженням структури папок** (особливо `.github/workflows/`). Не змінювати наявні сценарії Facebook і Telegram.
3. У GitHub → **Settings → Secrets and variables → Actions → Secrets** додати/перевірити:
   - `NGO_GRANTS_AI_BOT_TOKEN` — ви вже додали (токен BotFather).
   - `CF_ACCOUNT_ID` — ідентифікатор облікового запису Cloudflare.
   - `CF_API_TOKEN` — окремий **API Token**, обмежений правами **Workers AI Read/Edit** для потрібного Cloudflare-акаунта. Не використовуйте Global API Key.
4. У GitHub → **Settings → Secrets and variables → Actions → Variables** створити `NGO_AI_AUTOPUBLISH = false` на час тестування.
5. Відкрити **Actions → NGO Grants — AI catalogs**. Обрати **Run workflow**, у полі `dry_run_topic` написати `гранти для кіноіндустрії`. Це створить PDF **без виклику Telegram чи ШІ**. У вкладці запуску відкрити **Artifacts → ngo-grants-demo-catalog** та переглянути активні посилання.
6. Запустити вручну ще раз із **порожньою темою**; перевірити лог `Отримати запити ...`. Якщо `NGO_GRANTS_AI_BOT_TOKEN` правильний, бот оброблятиме звернення. Напишіть `/start` боту в Telegram, почекайте наступного запуску (планувальник зазвичай працює кожні 15 хвилин, але GitHub Actions інколи запізнюється).
7. Після перевірки приймання запитів та коректності PDF, і після додавання Cloudflare Secrets, встановити **Variable** `NGO_AI_AUTOPUBLISH = true`. Каталоги публікуватимуться самостійно. Для пробного невеликого навантаження почати з однієї теми.

> Важливо: поки `NGO_AI_AUTOPUBLISH` не `true`, **можна приймати запити й накопичувати чергу, але PDF у канал не публікуються**. Якщо нема CF-секретів, PDF теж не створюються автоматично.

## Команди

- `/start` або `/help` — інструкція.
- `/catalogs` — посилання на останні опубліковані PDF **у каналі**.
- Звичайне повідомлення темою — новий запит (один на день). Бот відповідає лише про приймання чи наявний каталог, **не надсилає персональні файли**.

## Запобіжники та обмеження

- У GitHub публічно зберігаються теми запитів **без типових контактних даних**, HMAC від ідентифікаторів користувачів, черга, посилання і створені PDF. Не зберігайте у темах персональних або конфіденційних деталей. GitHub зберігає історію файлів.
- Запуск за графіком GitHub Actions може затримуватися. Це **не миттєвий чат**.
- Відбір конкурсів виключно за публікаціями каналу. **Немає повторної перевірки першоджерел**. Відкидаються публікації без явно зазначеного дедлайну; це може виключити окремі придатні можливості, але зменшує кількість застарілих.
- Якщо дедлайн у дописі змінився або дата некоректна, потрібно оцінити матеріал вручну; без доступу до зовнішніх джерел достовірність не гарантується.
- Якщо Cloudflare квота завершилась або модель недоступна, обробка нового каталогу **призупиняється**; запит залишається в черзі, платний резерв автоматично не запускається.
- PDF посилаються лише на публікації каналу (не на грантодавців), а ті вже містять зовнішні посилання.
- **ВАЖЛИВО:** за нестабільної мережі під час опублікування/PUSH GitHub можливі повтори. Для бойової системи при великій аудиторії бажано перенести ідемпотентний стан до транзакційного сховища (Cloudflare D1). У цьому випуску передбачений тестовий/малий трафік.
